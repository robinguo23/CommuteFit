# 50 岗位、7 品牌地点搜索实测（2026-10-29）

结论：不能把“正确品牌名＋分店区域名”当作永远可靠的唯一规则。保留城市能减少跨城市误匹配；原始候选覆盖明显高于目前的自动聚合通过率，下一步应先改筛选与歧义处理。

## 样本与范围

50 个不同门店岗位：M&S 10、Tesco 10、Sainsbury’s 10、Boots 8、Greggs 8、Lidl 2、Co-op 2。范围为 London / Greater London；包括 Ham、Croydon、Ilford、Sutton、Heathrow 等。Boots 内的 Liz Earle 岗位按实际工作场所 Boots 搜索。

来源保留于 samples.json。41 条源自官方职位详情页，2 条源自官方职位列表，7 条源自搜索索引里的官方职位列表。含已过期职位；未重新确认所有岗位仍开放，不能用于展示“50 个可投递岗位”。列表来源不伪装成独立详情页。每条对应不同品牌／门店组合。只人工整理已有品牌、Store、Location 字段，本次没有验证岗位提取器自动生成这些字段的能力。

## 固定条件与四种查询

同一正在运行的后端、同一三源聚合算法和最多每源 8 个候选；不在测试中更改阈值或筛选。每次调用 /api/place-search/consensus，同时使用 LocationIQ、ArcGIS、TomTom。前端逐条执行，间隔 1.1 秒，完全相同查询复用已取得响应；200 是样本×规则的观察数，并非 600 次一定全新的上游请求。完整响应、查询串、时间和耗时在 results-2026-10-29.json。

| 规则 | 实际构造 | 共同区域 | 距离符合 | 距离超出 | 无共同区域 |
|---|---|---:|---:|---:|---:|
| R1 raw-title-location | 品牌＋原岗位标题＋城市 | 0/50 | 0 | 0 | 50 |
| R2 brand-area | 品牌＋简化分店标识 | 30/50 | 27 | 3 | 20 |
| R3 brand-store-city | 品牌＋原分店标识＋城市 | 23/50 | 23 | 0 | 27 |
| R4 brand-area-city | 品牌＋简化分店标识＋城市 | 28/50 | 27 | 1 | 22 |

简化仅移除 Simply Food、Foodhall、Superstore、Express、Extra、Local、Store(s)，展开 Rd→Road、St→Street，合并空白。保留已有街道、门牌、商场等标识；没有凭空推断行政区，也未将所有分店缩成城市名。R1 是“原样丢入标题”的负对照；部分品牌的岗位标题本来没有门店，且现有聚合器会要求岗位词也吻合，所以 0/50 不能解释成各地图供应商都搜不到门店。

测试没有前端请求异常；各来源也没有返回 unavailable。没有共同区域与网络错误分开记录。

## 独立核验口径

以官方招聘地址或品牌官方门店地址的邮编作参考，通过 Postcodes.io 得到邮编中心坐标；比较自动采用首组的代表点与参考点的球面距离，阈值 <= 965.6064 米（0.6 英里）。这是“附近区域可用”指标，不是精确分店正确率，也不代表步行距离或保证通勤时间误差。聚合组内 0.6 英里直径与此独立核验是两个不同检查。

references.json 保存地址来源；reference-coordinates.json 保存基准 API 响应。46 个有效邮编直接命中；4 个只能查询历史邮编，其中 J04/J09/J21 使用已标记历史中心。J36 的 TW6 2RQ 历史中心与 T5 相差数公里，弃用该坐标，以 Google Maps 明确列出 Unit RU032 Terminal 5 Arrivals、链接 Boots 店号 1978 的结果作为航站楼区域参考。J17 为 2024 年公开门店表，J06 London Victoria 标签不区分邻近几家 M&S，仅作该片区域核验。J24 原职位页复查 404，另以 Yell 地址交叉确认。

这些限制和当前地图数据的变动意味着不能宣称“百分百敲定位置”。M&S Tottenham Court Road 返回旧门牌 55，而官网现为 15–17：相距约 273 米，按用户的区域标准通过，绝不记为精确门店匹配。Boots White City 返回另一处附近门店，约 544 米，同理。

## 最关键的失败与漏筛

1. **Tesco Waterloo Road**：R2 采用 Poole 的 Waterloo Road，距 London 参考约 156 公里；R4 正确落回 London。城市不可随意删除。
2. **Sainsbury’s Waterloo**：R2 采用 Romford，距目标约 21.6 公里；加入 London 后通过附近区域核验。
3. **Sainsbury’s Wandsworth Road Local**：目标 646–650 Wandsworth Road / SW8 3SB，R2/R4 采用 Vauxhall 的同品牌同路另一端，偏约 2.2 公里。London 也不能消除同一长路多分店歧义。R3 没有自动采用，较保守。
4. **M&S Pantheon**：LocationIQ 已返回 173 Oxford Street / W1D 2JR，其他来源没有可靠共同候选；不能把专有分店名当作所有地图都认识的普通地名。
5. **Tesco Vauxhall Station、Sainsbury’s Bloemfontein Road、Co-op Berwick Street**：R4 原始结果中三源均有附近点，但最终没有共同区域。需检查品牌／区域词覆盖、可选精度和坐标补证规则，不能全部归因于供应商没数据。

R4 原始候选中，LocationIQ 至少一个附近点 36/50（首项 34），ArcGIS 41/50（首项 35），TomTom 38/50（首项 35）；三源联合至少一个附近点 **48/50**。这是“候选里存在”的召回观察，不是安全自动选择率，也不说明三源独立。当前自动选择只有 27/50 符合区域标准。四种规则正确自动采用的并集为 30/50，是事后上限，不可拿独立参考答案在线挑选后冒充可部署策略。

## 第一轮代码优化（2026-10-29）

基准指出，Sainsbury’s Wandsworth Road 的三源首选点集中在 SW8 2LF（Vauxhall），但 TomTom 同一响应还返回了 646–650 Wandsworth Road 的 SW8 3SB 候选，二者相距约 2.2 公里。之后用户确认三源共识组本身相距 88 米，可用于附近通勤初筛。本轮修正为：这组共识应保留为可用区域；远处单一候选列为组外结果，只有另有至少两个来源共同支持远处区域时才触发歧义。这样不跨区域平均，也不让单一远点抹掉强共识。

另外，完整 postcode 查询现在要求候选 postcode 完全相同；撇号和 `rd/road`、`ave/avenue` 规范化，解决常见书写差异。定向用例涵盖这三项行为。该规则保护多源独立共识，仍不代表核实了具体门店入口；原 50 样本需在新规则稳定后完整重跑。

### 无坐标共识时的文字回退

用户提出没有坐标共识时回看各家返回地址里的街道/区域名称。本轮在 Demo 中增加低置信度回退：候选品牌和非通用地点词必须都能在名称/地址里找到；忽略 `London` 等宽泛城市词；只有所有文本匹配点仍集中在同一 0.6 英里范围内，才显示一个 `text-match` 候选，并明确标记“没有多源共识”。如果同一街道词命中多个分店区域，仍然歧义，不按单一来源或供应商数量硬选。

Wandsworth Road 说明了这个限制：TomTom 返回了 646–650 Wandsworth Road / SW8 3SB，但 LocationIQ 和 ArcGIS 返回 SW8 2LF / SW8 2ET；这些地址共享同一条街道，文本重合不足以分辨哪家是招聘广告目标，所以仍无安全唯一回退。Bluewater 仍由三源共识得出 DA9 9SD。此逻辑只在 Demo 展示和标记候选，不改正式通勤流程。

## 基于首轮实测提出的方向（历史记录）

- 招聘已有完整邮编时保留并校验，避免丢掉更强的已知信息再重搜门店。
- 默认测试方向用“规范品牌＋保留辨识信息的分店地点＋城市”；保留原始门牌、邮编、分店别名供结果核对，不能一律删除所有后缀。
- 短查询用于找候选，原始已知地点用于约束；仅两源坐标靠近不足以证明找对长路上的分店。
- 先修已知漏筛，增加同路多分店保护，再用保留的 50 条做回归；不能直接放宽过滤来追求通过率。
- 本轮样本不是随机抽样，品牌和难例数量不均；R4 是观察首轮失败后的追加规则，未做独立留出验证。不能把这些结果外推为全 London 成功率。

```bash
python3 scripts/analyze_location_benchmark.py
```

输出 scored-results.csv（200 条）和 summary.json。原始观测不随重算改变。frontend/public/location-reference-check.html 是独立基准工具，手动点击才请求 Postcodes.io；正式通勤流程没有接入该工具。
