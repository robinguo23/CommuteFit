# Feature Specification: 可用于 TfL 的精确地点选择

Created: 2026-10-29. Status: implementation packaged; one live pasted-job/location-confirmation/fortnight-journey flow accepted after user restart, with manual search refinement. 用户授权独立位置模块、五类 TfL 端点回归，并连续完成交付。完整名称自动匹配仍有限制，具体验证边界见 CHANGELOG.md。

## User Scenarios & Testing

### US1 搜索并确认工作地点（P1）
用户用门店名/地址搜索，在带地址、来源和精度的候选中预览地图并明确确认。已确认候选同时成为 TfL 端点，不能只保留显示文字。
验收：同名分店选 B 后查询 B 的坐标；输入改变清除选择；没有门店候选不偷偷改成车站。

### US2 支持五种 TfL 位置格式（P1）
支持 WGS84 lat,lon、完整英国邮编、NaPTAN、ICS 和自由文本。直接输入的 ID/坐标只声明格式有效，不假定地点存在。自由文本消歧后使用返回的精确值重查。
验收：五种参数在起点和终点正确编码；坐标顺序不颠倒；HTTP 300 消歧的 parameterValue 可选择并重查。

### US3 未知和提供方失败可恢复（P2）
无候选、低精度结果、限流、服务不可用或 token 过期时说明原因；可编辑重新搜索或输入官方邮编。不得判为通勤不符合。

## Functional Requirements

- FR-001: 提供独立地点搜索 API，兼容现有 /api/locations 和 Journey 查询；服务端令牌绑定确认候选的显示文本与实际 routeValue，十分钟有效，不落库。
- FR-002: 固定提供方搜索仅在用户明确点击时进行；门店/地址候选优先，TfL 站点作为明确分类的候选，不替换门店。限量结果、临时缓存及提供方调用限频。
- FR-003: 用户能看名称、地址、postcode（若有）、精度、来源；有坐标时可预览地图，确认后填工作地点框。粗粒度 locality/street 只供细化，不可确认为精确门店。
- FR-004: 第三方 sourceId 不直接传 TfL；GeoJSON lon,lat 转 lat,lon，验证数字有限、范围有效。邮编可以直接作为 TfL 端点，显示邮区精度；不能伪造门牌或门店坐标。
- FR-005: 输入变化清除确认；时间模式/日期变化保留选择；往返交换各自令牌；令牌过期不能静默按名称重搜。
- FR-006: 自由文本消歧使用 parameterValue 优先，允许 place.id/naptanId 兼容；绑定候选显示名以允许 UI 改名后的重查。
- FR-007: 不使用付费服务、不调用大模型。默认 Photon 公共 demo 仅限合理低频测试、无可用性保证；可配置自托管 URL。正确显示 OSM/提供方署名；不使用 Nominatim 官方公共 API 作自动补全。

## Success Criteria

五种类型 × 起终点的传参及编码测试通过；同名分店、坐标顺序、非法坐标、修改输入、消歧选择重查有自动化回归。完整门店确认与 TfL 路线查询可按 quickstart 独立验收。测试结果明确区分模拟数据与真实接口观测，不承诺所有门店数据存在。

## Non-goals / Assumptions

位置服务与候选选择独立于岗位提取。无需全球自托管地理库、账号、位置历史、付费数据或自动翻译地址；建筑点不保证是员工入口。第一次外部位置请求由用户点击触发。用户明确确认邮区时可以用 postcode 查询，但提示其不同于门店入口。JSON 来源不可用于任意外部请求 URL。

## US4 多源区域共识 Demo（2026-10-29）

用户接受近似工作区域；每次显式搜索同时调用 LocationIQ、ArcGIS、TomTom，不追求入口。新增 /api/place-search/consensus；保留三个独立测试入口。各源最多 8 个点；有效英国候选按名称和区域查询词覆盖做保守筛选，不改写原请求；可查看被排除的原始结果。任意两点距离 <= 965.6064 米才可在同组，每源一票。三家支持优先，两家也可用；同源重复、单源或服务失败不增加票数。多处区域不可静默平均。代表点使用真实候选中总距离最小者，保留令牌；显示近似位置、来源、最大距离、筛选原因。无共同区域保留手动确认候选；未知不可当通勤失败。此轮仅 Demo，不迁移正式评估流程。名称过滤启发式非语义保证，缺字段或别名可漏匹配。


2026-10-29 实测修订：允许品牌吻合、地址缺查询区域的候选，通过另一来源原始文本合格点在 965.6064m 内的坐标补证参与；补证点不能递归作 anchor。返回 corroborated 列表解释补证；最终分组直径上限不变。四门店Google人工核对详见 multi-provider-live-review.md。


2026-10-29 用户明确不提供区域选择步骤：自动采用来源数最多的组，同票按组内最大距离最小优先，完全相同时保持稳定顺序。API selectedCandidate 明确返回首组代表点；有共同区域统一 supported，无共同区域仍未知，不能强造位置。Demo 只展示自动采用组，无区域选择按钮。此修订替代前文多组要求用户选择的规则。


## US5 多品牌搜索规则基准（2026-10-29）

用户要求从不同品牌招聘网站采集 50 个不同门店岗位，比较地点查询规则。基准独立于正式通勤流程，保留官方来源、已知过期状态、查询串和原始结果；固定三源算法与 0.6 英里阈值。分别统计共同区域、独立参考附近、超出范围、未知及请求错误；不得把候选覆盖或多源一致当作正确率。允许本轮显式批量实验，间隔执行并复用相同请求。报告披露历史招聘、地图区域精度、手工抽取字段、非随机样本及追加规则的限制。
