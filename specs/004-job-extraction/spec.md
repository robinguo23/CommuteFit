# Feature Specification: 职位信息提取模块

**Created**: 2026-10-29
**Status**: Implemented within first-release scope; automated validation passed; live website coverage not measured
**Input**: 用户提供职位 URL，无付费大模型 API；独立提取模块供通勤检查调用。

## User Scenarios & Testing

### US1 — 提取可确认的工作地点 (P1)
用户提交公开职位链接或粘贴正文，看到工作地点候选和来源。多个地点需选择，不能静默使用总部或推荐岗位地址。
Independent test: 输入包含 JobPosting 与总部地址的页面，仅工作地点成为候选；多个 JobPosting 不拼接为一个岗位。

### US2 — 正确理解岗位时间 (P1)
用户看到分日的实际班次、雇主排班窗口、每周工时和原文依据；只能明确选择实际班次来预填通勤表单。
Independent test: 同时包含 06:00–22:00 窗口与两个轮班的文本，窗口不得自动成为实际班次；24:00 结束归次日。

### US3 — 获取失败可继续使用 (P2)
链接无效、受限、动态空壳、过期或没有必要字段时，解释状态并允许粘贴或手动补充。部分字段可用也能展示。
Independent test: 无法访问链接返回明确失败状态和补填路径；用户新提取不得混入上次岗位字段。

## Requirements

### 2026-10-29 用户验收修订（优先于旧版单班次行为）

- 有可查询的实际班次时，仅展示并查询实际班次；没有实际班次时才使用雇主可排班窗口作为边界参考；两者均无才使用行业参考。
- 提取班次支持多选，默认选中全部优先班次。查询每个已选班次的去程与回程，不再局限一个班次。
- 只有原文明确星期才能限制查询日。未说明、每周五天、七天选五天含周末等情况，覆盖七天查询；这只是交通查询覆盖范围，不宣称岗位七天上班。
- 保留中文/英文星期和 Week 1 / 第一周、Week 2 / 第二周，不能把不同周的同一天合并。周期起始日期未公布时，由用户指定第一周的周一作查询日期基准；不猜真实 rota 的周期锚点。
- 门店名称加城市可作为候选地点，不要求原文一定有 postcode。必须标注门店候选待地图确认，不伪造地址/经纬度或替换成附近车站。
- 用户提供的 M&S Woolwich 双周样例作为固定回归样例：第一周日08–12、一04–10、六06–10；第二周一04–10、三04–08、五04–08，共六条分周班次。

- FR-001: 接受 URL、职位文本和直接工作地点；内容长度有限制。无需付费模型、账号或数据库。
- FR-002: 返回来源、提取方式、候选地点、时间证据、缺失字段、警告及岗位有效状态。所有机器提取值待用户确认。
- FR-003: 在清理页面前读取岗位结构化信息；允许 JSON 数组和嵌套对象。多岗位页面须保留歧义，不能自动拼接。
- FR-004: 不把公司总部当工作地址；不把城市当完整邮编；规范化英国邮编。多个候选必须显式选择。
- FR-005: 保留多条时间证据及其星期。区分 exact-shift、availability-window、weekly-hours、vague-shift、opening-hours、unknown；识别 12/24 小时制和 24:00 结束，跨日必须明确显示。
- FR-006: 单个无歧义实际班次可以作为可编辑建议预填；多个班次由用户选择。仅窗口或模糊时间不得自动填为实际班次。
- FR-007: 新岗位提取清空旧提取的地点和时间，保留用户个人出发地点、上限及 availability。
- FR-008: 公开页面获取限定公网 HTTP(S)、端口 80/443，无凭证；连接使用经过验证的 DNS 地址；最多三次受控重定向，总下载与等待时间有界。不会访问私网或携带用户浏览器登录信息。
- FR-009: 获取、解析和通勤评估分离；新提取 API 独立可调用，现有入口委托新模块。提取不调用 TfL 或 FareTo。
- FR-010: 明确静态获取与规则解析的边界；JS 渲染、验证码、受限页面暂以补填处理；不得宣称全站点精确覆盖。

## Key Entities

ExtractionResult、Source、LocationCandidate、ScheduleEvidence、Warnings。详见 data-model.md。

## Success Criteria

- SC-001: 自动化样例中的所有排班窗口与营业时间均不被自动预填成实际班次。
- SC-002: 所有返回地点与时间均带来源依据；多个候选不会被静默取首项。
- SC-003: 获取失败和缺失时间均可通过粘贴/手动补充继续通勤流程。
- SC-004: 接口契约、解析边界和既有提取行为有自动化回归测试；不把样例通过率宣传为真实网站覆盖率。

## Assumptions / Non-goals

独立模块先在现有项目内部署；未来可替换获取器。暂不引入浏览器服务、通用 ATS 全覆盖、网站登录、反爬绕过、批量爬取或持久存储。第一版不保证恢复未公布的 rota。用户已授权此范围，无待确认项。
