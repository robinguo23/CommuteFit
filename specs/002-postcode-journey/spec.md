# Feature Specification: Postcode Journey / 邮编路线查询

**Created**: 2026-10-27
**Status**: Implemented; live acceptance pending
**Input**: 用户输入出发地和目的地（英国 postcode、站名、地址或地点名称），返回相关路线和每条路线全程总价。

## User Scenarios & Testing

### User Story 1 — 查询路线与全程价格 (P1)
用户输入出发地和目的地，默认查询现在出发的伦敦公共交通路线；也可选择指定日期及具体时分，按出发或到达时间查询。支持英国 postcode、车站名、地址或地点名。无需档案、数据库或其他必填设置。
**Why this priority**: 先完成最小可用路线查询闭环。
**Independent Test**: 输入两个可解析的地点，查看每条路线的时间、途经站点、换乘和独立全程价格；地点有歧义时先选中正确候选。
**Acceptance Scenarios**:
1. TfL 可解析输入并返回多条路线时，每条独立展示出发/到达时间、全程耗时、交通段和全程总价。
2. 全程总价缺失时显示“票价暂不可用”，不以分段金额凑总价，也不当成免费。
3. 地点存在歧义时可根据 TfL 返回的候选名称和类型选择对应地点；修改任一地点输入后旧候选失效，但已显示的路线结果继续保留，直到用户发起下一次查询。
4. 缺少地点时提示对应字段；TfL 无法解析时建议用户输入更具体的地址、街道或车站；请求失败可重试；正常空结果与请求失败分别显示。
5. 查询期间编辑输入，不得显示旧请求对应的结果。
6. 默认选择 NOW；选择 Leave 或 Arrive 后，用户可选日期及具体时分，结果明确显示使用的时间语义和伦敦当地时间。
7. 时间模式保留本地化的三个并排选项（中文“现在/出发/到达”，英文“Now/Leave/Arrive”）；模式、日期或时间变化后自动查询；指定时间时，左侧时间框点击后显示 15 分钟间隔选项，左右微调按钮放在时间框内；日期位于右侧，日期框贴合文本且显示星期，并提供前后日期按钮；日历作为浮层覆盖内容，点击控件外或按 Escape 时关闭。

### Edge Cases
- TfL 无法解析的地点、输入过于宽泛或返回多个候选；起终点相同；全程价格缺失；跨午夜路线。
- 提供方返回空数组、无效结构、超时、限流或地点候选。

## Requirements

### Functional Requirements
- **FR-001**: 页面只有出发地和目的地两个必填字段，接受英国 postcode、车站名、地址或地点名称；查询提示和候选选择支持中英文。
- **FR-009**: 浏览器对缺失或格式错误 postcode 的原生校验提示按当前界面语言本地化；用户编辑字段后清除旧校验提示。
- **FR-010**: 每条路线总价旁显示 TfL 路线票价项返回的 `chargeLevel`（例如 Peak 或 Off Peak），按界面语言本地化；未返回时不推断时段。
- **FR-011**: 路线及交通段时间仅显示时分和对应耗时，不重复显示日期；交通方式标签避免重复线路名称，英文步行显示为 “Walk”；TfL 提供停靠站数据时，在交通段起终点后显示站数，缺失时不推断。
- **FR-002**: 合并多余空格；英国 postcode 规范化大小写和分隔空格，地点文本保留可读格式；默认现在出发。用户可选择 Leave 或 Arrive，并输入指定日期与 24 小时制时分；显示伦敦时间查询依据。
- **FR-003**: 查询 TfL 相关路线，显示完整行程交通段、时间、耗时和换乘，不只显示第一段。
- **FR-004**: 只使用 Journey Planner 返回的每条路线级 `fare.totalCost` 作为全程总价，并显示 TfL 返回的 `chargeLevel`（若有）。若 `totalCost` 缺失或无效，明确显示票价暂不可用；不调用未列入公开 Swagger 的 FareTo，不按 leg 累加或自行推算价格。
- **FR-005**: 区分正常无路线、无法解析地点、服务失败和缺少票价。
- **FR-006**: 查询前告知出发地和目的地文本将发送给 TfL；输入、结果不持久化。
- **FR-007**: 保留 TfL 署名和计划班次、不保证实时到达说明。
- **FR-008**: 时间模式保留本地化三个并排选项；切换模式或修改日期、时间后自动查询；查询期间保留已显示路线结果，新结果返回后替换；指定时间时，左侧时间框打开 15 分钟间隔菜单，前后微调按钮放在框内；右侧日期框显示月日和星期、不显示年份，日期与前后日期按钮放在同一边框内；日历以覆盖页面的浮层展示，选择日期后立即关闭并查询，时间菜单只滚动自身，打开时页面位置不变；点击控件外或按 Escape 时关闭。
- **FR-012**: 地点输入停顿 500ms 后，对至少 3 个字符的非 postcode 查询后端候选接口；先搜 `StopPoint/Search/{query}`，站点候选少于 5 项时再用 `Place/Search?name=...` 补充，合计最多显示 8 项。下拉项显示地点名称和类型；用户选择后填入规范名称并保留短期服务端 token。输入 postcode 时跳过候选请求，由 Journey Planner 解析。两端都有输入时，选择候选立即触发路线查询；若另一端为空，等用户选好或填写后再查询。Journey Planner 仍返回歧义候选时要求用户明确选择；TfL 没有联想匹配项时允许用户直接提交自由文本。

### Key Entities
- Journey query: 出发地和目的地文本、查询时刻、临时地点候选。
- Journey option: 起终点、交通段、时间、耗时、全程报价及状态。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 用户仅填写两个字段即可完成查询，无档案创建步骤。
- **SC-002**: 至少 5 个代表性响应中，每条可用路线的交通段、耗时及全程总价与提供方一致。
- **SC-003**: 缺价、空路线、异常响应测试全部明确区分，不出现虚构总价。

## Assumptions
- 首版是路线列表与价格，不包含交互地图绘制或逐步导航。
- 默认现在出发；指定 Leave/Arrive 时间属于当前范围。返程、班次、周末、优惠、封顶、历史记录均延后。
- TfL 并非所有路线都有总价；首版不能保证每次均返回数值。
- 原 001 功能作为历史方案保留，当前交付以本规格为准。
